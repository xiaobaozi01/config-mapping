# GNS3 路由器配置自适应系统需求规格

## 1. 文档目的

本系统将真实网络中的 Cisco IOS XR 与 Juniper Junos 配置，以及描述设备和物理链路的 Excel 拓扑，转换为可导入 GNS3 的 XRv9000 与 vMX 配置。系统重点解决虚拟镜像接口数量、接口名称和真实设备不一致的问题，并清理实验环境不可用的认证配置。

本文档是首版实现和验收的基线。华为设备不参与配置转换，只作为拓扑对端；涉及华为设备的链路仍按本端 Cisco/Juniper 端点完成 NNI 适配。

## 2. 输入

### 2.1 拓扑文件

输入为 `.xlsx` 文件，包含两个工作表：

- `设备列表`：设备名称、厂商、配置文件。
- `链接表`：A 端设备、A 端物理接口、Z 端设备、Z 端物理接口。

程序兼容需求中定义的常用中英文列别名。额外工作表和额外列应原样保留。链接表中出现的物理接口均为 NNI。

### 2.2 配置文件

- Cisco 输入配置：IOS XR 文本配置。
- Juniper 输入配置：Junos 大括号层级格式。
- 设备列表未指定配置文件时，程序按设备名称匹配 `.cfg`、`.conf` 或 `.txt`。

### 2.3 镜像接口配置

镜像配置文件描述 XRv9000 和 vMX 在 GNS3 中的镜像名称、可选版本、实际可用的数据接口列表和模拟参数适配策略。前 n-3 个接口分配给 NNI，倒数第二个承载 UNI，另外两个末尾接口预留。

## 3. 术语和分类

- NNI：端口出现在 Excel 链接表中。
- 非 NNI：不属于链接表端点及其聚合、子接口闭包的物理或聚合接口；其中有效业务按 UNI 汇聚输出。
- Loopback：逻辑环回接口，编号和地址保持不变。
- 管理接口：XR 的 `MgmtEth` 及 Junos 的 `fxp`、`em` 等接口，不参与业务接口映射。
- 聚合接口：IOS XR 的 `Bundle-Ether` 或 Junos 的 `ae`。

## 4. 功能需求

### 4.1 NNI映射

1. NNI 按 Excel 链接表行号稳定排序。
2. 每条有效 NNI 链路在两端分别按本端厂商和镜像 Profile 分配目标物理接口；Cisco XRv9000 与 Juniper vMX 可以互联，两端目标接口名称不要求一致。
3. 同一对端间经两端确认属于同一聚合的多条成员链路压缩为一条，保留最早 Excel 行并映射物理成员；Bundle/ae 主口与子接口保留名称、地址、封装及协议引用。成员绑定随目标物理口重建，最小活动成员数调整为 1，最小活动带宽门限删除并报告，静态/LACP 模式保持原值。
4. 同一聚合跨不同对端时默认报错；例外是配置或 peer-link 拓扑能够确认的华为 M-LAG，分别压缩每台华为的成员并各保留一条连接，本端逻辑聚合和业务不拆分、不复制。同一本地 Bundle 扇出到同一对端的多个 Bundle 或拓扑成员与配置绑定无法对应时失败。链路两端聚合协商方式不作正确性审计，按输入原值保留；单端 Bundle、对端普通口的链路作为非对称混合链路保留并告警。带地址、VRF、L2 transport、bridge/unit/family 或子接口的独立业务成员保留且不参与压缩，其他成员仍可压缩。
5. 普通 NNI 物理接口的配置和全局引用改为目标物理接口。
6. NNI 数量超过可分配物理接口时，转换失败并报告错误。
7. 系统不审计链路两端的 IP、VLAN、MTU 或封装一致性，此类业务一致性由输入配置保证。
8. 华为设备不参与配置转换，只作为链路对端；配置存在时只读提取聚合成员和 M-LAG 配对信息，聚合核验所需信息缺失时明确报错。普通链路仍可不提供配置文件。与华为相连的 Cisco/Juniper 端点仍按本端 Profile 分配目标 NNI 并改写本端配置和拓扑接口，华为侧设备行与接口名保持原样。
9. 华为与华为之间的链路原样保留在适配拓扑中，不产生接口映射；只有对端厂商无法识别或端点未登记时才跳过链路。

### 4.2 UNI 业务迁移

1. Group 展开和接口分类后，依据原始拓扑及聚合关系计算 NNI 保留闭包，预检跳过端点同样受保护；范围外的物理、聚合接口按 UNI 处理。
2. 只迁移有 IP、有效二层业务或外部引用的业务单元；无业务裸口删除。UNI 源父树先暂存以释放原名称，NNI 完成后再迁到共享口，避免接口重名混合业务。
3. 共享 UNI 固定为倒数第二个物理口。默认单层 VLAN，原有 QinQ 保留双层结构与内层标签；每设备为业务分配唯一外层 VLAN（2～4094），优先保留原值，冲突时分配最小空闲值。先预留可保留的原标签，分配顺序按规范化源接口名固定。
4. 保留地址、VRF、routing-instance、协议和二层业务绑定，并统一改写接口引用。BVI/IRB 按原类型保留及维持桥域网关关系，不迁成物理子接口。
5. UNI 聚合业务扁平化为共享子接口，移除原物理成员及失效聚合属性并告警；成员有独立业务或绑定不唯一时拒绝迁移。NNI 聚合主口及子接口继续按原类型保留。
6. UNI 迁移处理业务封装及失效聚合属性；硬件、介质、速率和时钟由现有 post_rewrite YAML 清洗按路径和开关删除。源父口暂存树保留到清洗完成，再由兼容阶段检查剩余父级业务配置并清除，不新增前置清洗或硬件定义提取。必需且可以安全共享的父口配置单独迁移，介质 MTU 取最大值，ethertype 冲突报错。转换记录命令路径及原因，普通清洗沿用规则命中统计。
7. 无法安全重建的标签范围、通配封装、二层重编号或父级业务依赖始终报错并停止发布部署配置，不受宽松输入校验或模拟 off 影响。不新增 GNS3 客户设备和接入链路，不保证端到端客户通信。
8. UNI 映射使用 `role=UNI`，业务 `action=map`，网关 `preserve`，裸口 `remove-bare`，已扁平化聚合成员 `remove`；业务映射记录源、目标和内层 VLAN。多业务父口的歧义引用不自动折叠到共享父口，交由最终完整性校验拒绝。
9. 聚合 NNI 的冗余成员缩减、依赖裁剪及已删除接口精确引用豁免保持现有行为。原始源语义审计继续关闭，UNI 迁移仅检查安全转换所需的约束。

### 4.3 Loopback和管理口

- Loopback/`lo0` 原样保留。
- 数据接口列表前 n-3 个用于 NNI、倒数第二个用于 UNI，其余两个末尾接口预留；默认八口中 0～4 为 NNI、6 为 UNI、5 和 7 预留。
- 源接口按 NNI 保护范围和业务识别处理，与其名称是否恰好为预留口无关；预留口不得作为 NNI 输出目标。
- 管理接口不参与转换，设备通过 GNS3 console 管理。

### 4.4 认证清洗

系统删除原配置中的本地账号、TACACS+、RADIUS、外部 AAA、SSH/Telnet 网络管理服务、SSH 信任和 SNMP 信息，并配置实验登录凭据：

```text
IOS XR 用户名：root
Junos 用户名：root
密码：admin123
```

- IOS XR 删除自定义 `usergroup`、`taskgroup`、`snmp-server`、SSH/Telnet server/client，以及 `line` 配置中对旧密码、认证方法、授权方法、计费方法和用户组的引用；保留与认证无关的 console 参数。新用户直接加入内置 `root-system`。
- Junos 删除原 `system login`、RADIUS/TACACS server/options、accounting、`system services` 下的 SSH/Telnet、`security ssh-known-hosts` 和顶层 `snmp`。只配置 root authentication，不新增 `system login` 用户。
- `report.json` 按账号、AAA、TACACS、RADIUS、usergroup、taskgroup 和 line 引用等类别记录删除数量。
- 转换报告不得回显被删除的秘密值。

协议认证、PKI、硬件、NAT 和流量统计的清洗规则默认启用。它们与 PTP 和接口类型约束清理规则按厂商定义在目标镜像目录的 `cleaning.yaml`；转换入口不接受外部规则文件。每条规则由布尔字段 `enable` 独立控制。同一 `category` 的定义与引用规则（如协议认证、流量统计）应同时开启或关闭，避免残留引用指向已删除对象。

GNS3 实验只验证路由协议。聚合类型与成员绑定保持；实验范围仍排除以下功能： LLDP/CDP、以太网 CFM/OAM、物理口残留的 BFD over Bundle、接口 QoS 挂载（IOS XR `service-policy`、Junos `class-of-service interfaces`）和 Junos 服务链（`service-set`、接口服务挂载、服务接口）默认删除；路由协议内的 BFD 不受影响。

### 4.5 保守清洗和扩展规则

除认证外，系统默认保留未知配置。可确认不兼容的配置通过统一 YAML 规则定义。每条规则必须声明厂商、启用状态、报告类别、完整父级路径、节点匹配表达式、动作和原因。`path` 使用 `[]` 表示顶层、`*` 表示一级、`**` 表示零级或多级。规则动作支持：

- `delete`：删除匹配配置。
- `replace`：替换匹配值。

声明式规则固定按先删除、后替换的逻辑执行。同一轮按 YAML 组内顺序选择每个节点的首条匹配规则；删除父节点后不处理后代，替换命中后不再级联替换该节点。替换父节点后，子节点使用更新后的父级路径。厂商实现可以在一次树遍历中模拟这两轮并合并提交，但不得改变该语义。任何规则命中均记录规则 ID、类别、数量和原因。

### 4.6 全局接口映射

系统维护结构化映射，而非简单字符串字典。每条记录至少包含设备、源接口、角色、动作、目标接口、关联 Excel 行和原因。物理端口映射与聚合自映射分别记录；不能将聚合业务引用展开到多个物理口。接口块、路由协议、MPLS、VRF、L2VPN、ACL、QoS等对接口的引用均使用该映射更新。

### 4.7 责任链

转换核心使用责任链模式。配置 group 必须在接口分类前展开，处理顺序为：

```text
CleaningRulesHandler(pre_analysis) -> TopologyPreflightHandler -> GroupExpansionHandler
-> PreconfiguredInterfaceCleanupHandler -> InterfaceClassificationHandler
-> UNIPreparationHandler -> NNIHandler -> UNIHandler
-> ReferenceRewriteHandler -> CleaningRulesHandler(post_rewrite)
-> InterfaceCompatibilityHandler -> SimulationAdaptationHandler -> FinalInterfaceValidationHandler
```

每个处理器只负责其领域的识别、映射、配置变更和报告，并将上下文传递给下一个处理器。后续处理器可插入链中而不修改已有处理器调用方式。

- `TopologyPreflightHandler` 在配置改写前校验端点，仅标记端点缺失或厂商无法识别/未登记的链路；跳过链路的本端接口仍以 `action=skip` 保留 NNI 角色，不得被 UNI 规划误迁或删除。华为设备登记到 `external_devices`，按仅适配对端处理，不在此处跳过。
- `InterfaceClassificationHandler` 只允许厂商白名单中的物理接口参与物理端口映射；未识别接口保留原配置并告警，若被链接表用作端点则转换失败。
- `CleaningRulesHandler` 只在 `pre_analysis`、`post_rewrite` 两个固定执行点运行。
- YAML 规则固定在 `post_rewrite` 执行；复杂规则通过统一接口声明执行点。
- banner 在 `pre_analysis` 整段停用；认证替换在 `post_rewrite` 的 YAML 规则之后，原子地清理旧认证并写入实验账号。

### 4.8 模拟参数适配

1. `SimulationAdaptationHandler` 在接口迁移、引用更新和认证清洗后运行，根据设备的镜像 Profile 调用厂商文档实现。
2. `simulation_adaptation.mode` 支持：
   - `off`：不执行参数适配；
   - `compatible`：只启用已映射的数据口；物理硬件属性已由 Cleaning 全局清理；
   - `stable`（默认）：在 `compatible` 基础上，将已经存在且过于激进的 BFD interval 和 multiplier 提高到 Profile 指定的安全下限。
3. 参数适配不得凭空开启 BFD，不得默认缩短 OSPF、IS-IS、BGP 等业务协议定时器，也不得修改未参与映射的数据口。
4. 参数适配必须幂等；每台设备的镜像、模式、目标接口和分类修改数量写入 `report.json`。

### 4.9 配置 Group 展开

1. Group 统一展开并校验所有活动引用及其完整依赖，不提供相关性筛选或原样保留模式；未被活动配置引用的模板不参与求值。
2. IOS XR 支持识别并展开活动的 `group ... end-group`、`apply-group`/`apply-groups`：
   - 精确接口选择器展开到对应接口；
   - 引号包裹的接口正则选择器按照已知显式接口和拓扑接口展开；
   - 显式配置优先于 group 中的同类配置；
   - 未定义 group、运行时变量或 group 内再次应用其他 group 等无法安全求值的情况触发转换失败；正则选择器当前无匹配对象时视为无继承结果。
   - 显式配置高于 group；内层 `apply-group` 高于外层；同一条应用语句中靠前的 group 优先。
   - 同一 group 中多个正则匹配时，按最长匹配优先，长度相同按表达式词法顺序处理。
3. Junos 支持识别并展开活动的 `groups {}`、`apply-groups` 和 `apply-groups-except`：
   - 支持根层级和局部层级应用；
   - 多个顶层 `groups {}` 容器必须规范化为一个容器，同名 group 定义的子配置按原始出现顺序合并；
   - 支持 Group 内递归应用其他 Group，并校验完整传递依赖；
   - 间接未定义引用或 Group 循环引用触发事务回滚；
   - 支持常见 `<ge-*>`、`<*>` 通配节点；
   - 显式配置优先于 group 继承配置；
   - 无法安全解析的已应用 group 触发转换失败，不输出不完整的自适应配置。
   - 显式配置高于 group；嵌套层级的 group 高于外层；同一 `apply-groups` 列表中靠前的 group 优先。
   - `inactive:` 节点及其完整子树不参与生效配置求值；最终输出时跳过该节点及其完整子树。
4. 展开后的配置进入后续 UNI 准备、NNI/UNI 迁移和认证处理器。成功展开后从输出中移除 group 定义及其应用语句，避免接口改名后再次引用旧接口。
5. group 展开必须采用事务模式：所有活动引用及其依赖均可安全解析时才提交展开结果；任一活动 group 无法解析时整体回滚并将本次转换标记为失败。
6. 配置冲突使用完整层级和语义键判断，不能只比较命令首关键字：
   - `ipv4 address` 与 `ipv4 access-group` 是不同配置；
   - Junos多个 `address`、接口列表等可重复配置应同时保留；
   - `mtu`、`description`、`vlan-id` 等单值配置按继承优先级选出唯一值。
7. 每个冲突记录层级、配置键、胜出/被覆盖的来源和值，并输出到 `report.json.group_conflicts`。
8. 配置键由 XRv9000/vMX 专属的路径感知规则包生成；规则未命中时不得静默覆盖任何语句。
9. `group_handling.unknown_identity` 支持 `preserve`、`warn` 和 `fail`；`fail` 遇到同路径同命令族的未知潜在冲突时必须整体回滚。
10. 报告必须输出 group identity 规则命中数、降级数、覆盖率和未知歧义数，供镜像语料持续补齐规则。

优先级语义依据厂商文档：Cisco IOS XR 配置组采用本地配置优先、内层组优先及最长正则匹配；Junos采用本地配置优先、嵌套组优先，且同一列表中第一个 group 优先。

## 5. 输出

输出目录包含：

- `topology-adapted.xlsx`：更新后的有效 NNI 拓扑；冗余聚合成员行被删除，华为设备行及其链路保留。
- `configs/<设备名>.cfg`：转换后的设备配置。
- `interface-mapping.json`：完整接口映射。
- `report.json`：错误、警告、删除和处理摘要。
- `README.txt`：导入说明和固定实验账号。

同目录重跑由内部产物清单管理：先前生成的可导入成果隔离到 `.previous-outputs/` 并报告位置，保留用户额外文件。输入加载、转换或最终校验失败均写失败诊断并撤下旧成果；新成果发布成功后才写成功报告。写出使用临时文件原子替换，不能穿透符号链接改写输出目录外的文件。

华为设备不转换；已有配置只读用于聚合核验，普通链路可无配置。与华为相连的保留链路仅改写 Cisco/Juniper 侧接口名；已核验 M-LAG 的每台华为各保留一条成员，华为接口名不变，华为之间的链路保持原样。

## 6. 失败和告警策略

以下情况必须作为错误，不得输出“成功”状态：

- 必需工作表或列缺失。
- 设备、配置文件或厂商无法识别。
- NNI 物理接口不足。
- 同一对端聚合组内的成员关系不一致。
- 已知目标接口类型冲突无法安全转换，或最终接口校验失败。
- 同一有效链路端点映射不完整。
- 配置语法结构无法安全解析。

源配置语义问题只在映射前检查一次，默认作为 warning 输出，包括单值/主地址冲突、接口类型与命令组合不匹配、L2VPN/网关角色不符合预期、重复 unit 及二三层 family 混用。调用方可用 `strict_input_validation=True` 将这些 warning 恢复为 error。最终阶段只检查适配产物的目标镜像兼容、聚合绑定和引用完整性，不重复执行源语义规则。解析失败、映射不唯一、聚合关系无法表达、目标兼容失败和转换后悬空引用不受该开关豁免。

未知但结构完整的非认证命令默认保留并产生可选告警。

## 7. 非功能要求

- Python 3.11 及以上。
- 相同输入产生稳定的接口分配与清理结果。
- 不在日志和报告中泄露原认证秘密。
- 转换过程不修改原始文件。
- 核心处理器、Excel解析、厂商配置解析和映射规则应可单元测试。

## 8. 首版不包含

- 华为配置转换。
- 华为侧接口名与配置适配；华为设备只作为拓扑对端。
- IOS/IOS XE/NX-OS 到 IOS XR 的语法转换。
- 非 NNI 接入业务的模拟和外部 GNS3 连接。
- 未经规则明确指定的大范围硬件配置删除。
- 包含运行时变量且无法静态求值的复杂配置 group；此类输入将明确报错，不生成转换配置。

## 9. 接口兼容与验收边界

目标接口兼容阶段在引用改写和清洗后执行，依据厂商、目标镜像及物理父口/L3 子接口/L2 子接口上下文处理已知限制。最终校验在模拟参数适配后执行，防止后续阶段重新引入非法状态。两者不受模拟参数 `off` 模式影响。未知但结构完整的命令不应被静默当作已验证能力。

自动测试覆盖转换语义、规则命中、依赖清理和失败时不输出配置；它不替代目标镜像的 CLI。当前未连接真实 XRv9000，必须另行使用实际镜像版本验证 load/commit 成功、父口和子接口状态、以及所需路由邻接。报告成功仅表示转换与静态校验完成。
