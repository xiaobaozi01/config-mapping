# 第三轮：增量接口索引与有预算的语义缓存

已完成这两项实现及本地验证。合成测试证明重复接口扫描和重复规则匹配明显减少；真实项目能否在 10 分钟内完成，仍以公司环境关闭 profiler 的完整运行结果为准。没有使用真实业务配置，也没有进一步裁剪业务或报告。

## 实现范围

### 增量接口索引

- 缓存规范接口名到活动节点列表、父口到逻辑接口、Cisco 点号前缀到接口树的映射。重复定义保留各自节点及源码顺序，首次匹配行为不变。
- 名称查找、重复定义合并、Cisco 接口树删除／改名／克隆和父口逻辑接口查询使用同一索引。
- 标量改名、活动状态变化、Junos unit 变化只更新受影响条目。容器尾部插入和删除增量维护；中间插入、顺序调整或容器整体替换重建接口容器索引。
- 通知来自 AST 的弱观察者，独立于回滚日志及其清理时机。根替换、失败回滚和文档复制不会复用旧节点；普通业务字段变化不会清空整个目录。
- 文档释放、预算逐出及任务结束都释放索引。容量不足时回到原有扫描路径；超预算索引不会因每次标量改名反复尝试重建。

索引仍需首次扫描接口容器。Python 子节点列表的中间插入、删除仍有列表自身的成本；本轮没有更换 AST 的列表表示。

### 语义匹配与 LRU

- 移除达到 16,384 条就整体清空的行为，改为共享预算内的 LRU，仅逐出必要的冷条目。
- 决策键包含编译规则包身份及完整不可变上下文：厂商、路径、语句、节点类型。不同规则包及不同任务不会串用结果；异常不缓存。
- 预编译静态路径及按节点类型、首个安全字面量划分的候选桶。每条冷语句只分词一次，再完整匹配所有候选；捕获开头及可能改变原有报错顺序的规则保留回退路径。
- 保留优先级、歧义错误、捕获约束及 opaque 回退语义。保留旧 `match_rule()`，用作完整决策及异常文本的差分参照。
- 路径分词和接口名称规范化使用同一任务预算。语句分词不重复存储，完整决策命中后也不再分词。
- 模块级解析器只持有静态规则，不跨任务缓存输入。独立创建的解析器和任务外的文档使用各自 16 MiB 的局部上限。

规则候选预编译本身不依赖输入缓存，预算为 0 时仍然生效。任务结束批量清空条目及底层容器，仅保留聚合计数，避免逐条重新计算键哈希和维护 LRU。

### 预算与观测

```python
context = convert(
    topology_path,
    config_dir,
    output_dir,
    cache_budget_bytes=2 * 1024**3,  # 默认值，按需分配
)
```

新增缓存共享默认 2 GiB 的估算预算，不预留整块内存。设为 `0` 关闭新增输入缓存。负数、非整数及布尔值在输入读取前被拒绝。

插入或索引增量变化时估算占用，不在每次读取时扫描缓存。接口索引计入新增名称、字典、列表、前缀桶及引用等元数据，已有 AST 不重复计费；语义条目按固定数据类型和字符长度估算。预算限制的是这些估算值，不能作为 Python 分配器或整个进程 RSS 的硬上限，插入前的临时构建也可能短暂占用内存。

`performance.json` 新增 `cache`，只含预算、估算峰值、剩余条目、关闭状态及各固定命名空间的命中／未命中／逐出／构建／更新等计数。正常结束后 `closed=true`、`entries=0`、`estimated_bytes=0`。成功、业务失败、异常及中断均清理；不输出配置、接口名、设备名或缓存键。

## 测量方法

环境：macOS ARM64、Python 3.12.13；原版基线为第三轮修改前的 `acb8fc7941e4c94c58155f33df766caaaaf510ea`。分项提交为：

| 提交 | 内容 |
|---|---|
| `ff4cf47` | 共享预算、聚合指标、可关闭缓存的复测入口及基准 |
| `2ae30f4` | 两厂商增量接口索引及调用方接入 |
| `728646b` | 语义 LRU、规则预编译和候选匹配 |
| `20da08a` | 减少冷语义条目估算成本，限制超预算索引重试 |
| `8a554b1` | 批量释放缓存，补齐接口前缀桶占用估算 |

最终验证资料随报告单独提交，以当前第三轮完整提交为准。

`benchmarks/third_round.py` 每项先预热一次，再取三次无插桩运行的中位数。cProfile 调用次数及 tracemalloc 峰值另跑，不混入正常耗时。基准计时包含首次索引构建、编辑和任务缓存清理；不包含 AST 解析、测试输入生成、静态规则编译、结果摘要生成或 profiler 汇总。这是热点操作实验，不是完整转换耗时。

内存列是在输入和 AST 准备完毕之后启动 tracemalloc 所测的操作阶段峰值，不是全进程 RSS，也不是把新旧峰值相减得到的缓存净增量。完整转换仍独立记录进程生命周期 RSS 高水位。

接口实验使用 5,750 个接口，执行 2,000 次查询，或 100 轮改名再恢复／克隆再删除，每轮编辑后立即查询。Cisco 约 2.3 万节点，Junos 约 1.7 万节点；两家 AST 结构不同。语义实验包含 100 条合成规则、18,000 个不同上下文，超过原来的整体清空阈值；它不代表真实规则包的分布。

## 最终热点结果

| 操作 | 修改前中位数 / 秒 | 修改后中位数 / 秒 | 操作阶段峰值 MiB：前 → 后 |
|---|---:|---:|---:|
| Cisco：2,000 次查询 | 3.9487 | 0.0383 | 1.36 → 4.88 |
| Junos：2,000 次查询 | 4.2749 | 0.0265 | 1.16 → 4.94 |
| Cisco：100 轮改名／恢复及查询 | 0.5811 | 0.0404 | 1.05 → 4.57 |
| Junos：100 轮改名／恢复及查询 | 0.5314 | 0.0347 | 1.00 → 5.03 |
| Cisco：100 轮克隆／删除及查询 | 0.7483 | 0.0531 | 1.13 → 4.67 |
| Junos：100 轮克隆／删除及查询 | 0.8198 | 0.0391 | 1.54 → 5.06 |
| 语义：18,000 条首次访问 | 3.4877 | 0.1838 | 4.09 → 8.94 |
| 语义：18,000 条访问两遍 | 7.1089 | 0.2217 | 4.09 → 8.94 |

以上是特定合成操作的改进，不能据此把旧版 70 分钟按比例换算成完整任务耗时。基准的配置摘要及计数与原版本一致；语义摘要仅覆盖匹配总数，完整决策一致性另由差分测试验证。

| 独立 profile 计数 | 修改前 | 修改后 |
|---|---:|---:|
| 每组 2,000 次接口查询中的 `interface_nodes()` | 2,000 | 0 |
| 每组 100 轮编辑及查询中的 `interface_nodes()` | 300 | 0 |
| 上述每组接口索引构建 | 无索引 | 1 |
| 上述每组编辑后的接口增量更新 | 无索引 | 200 |
| 冷语义规则完整匹配 | `match_rule` 1,800,000 | `match_prepared` 18,000 |
| 两遍语义规则完整匹配 | `match_rule` 3,600,000 | `match_prepared` 18,000 |
| 两遍语义 `_resolve_uncached()` | 36,000 | 18,000 |
| 两遍语义 `tokenize()` | 3,600,000 | 18,001 |

接口名缓存命中为 1,999 / 2,000；编辑实验为 299 / 300。两遍语义决策命中 18,000 次；路径分词命中 17,999 次。语义任务估算峰值约 21.52 MiB，无须预分配 2 GiB。

扩容实验另覆盖 11,500 和 33,333 个接口。后者约为 Cisco 13.3 万节点／Junos 10 万节点，2,000 次查询约 0.23～0.24 秒，操作阶段峰值约 25～27 MiB。每组仍只构建一次索引，稀疏编辑仍是 200 次增量更新，未退回每次编辑扫描整个接口目录。全部规模的明细见 JSONL。

### 缓存自身的代价

规则候选预编译是主要收益来源；LRU 的收益取决于重用率。使用相同预编译算法、只调整任务预算的对照如下，预算 0 的语义实验取五次正常运行中位数：

| 相同的 18,000 条简单语句 | 预算 0 / 秒 | 默认预算 / 秒 |
|---|---:|---:|
| 访问一遍 | 0.1390 | 0.1838 |
| 访问两遍 | 0.2746 | 0.2217 |
| 访问五遍 | 0.6512 | 0.2643 |

五遍实验的两侧均取五次中位数；启用缓存后 72,000 次决策命中，完整匹配从 90,000 次降到 18,000 次。简单语句全部首次访问时，插入、估算、LRU 及释放成本使本实验慢约 32%；不能把缓存描述为对所有输入都有收益。规则匹配较复杂或反复访问时更可能有收益，真实数据需查看候选数和命中率。预算 0 是可用的对照及回退方式，但同时关闭接口索引，不能把整个任务的差值全部归因于语义缓存。

最初的通用反射占用估算和重复语句分词缓存成本较高，已换成固定类型估算并取消重复存储。保留中间阶段数据以说明这项修正，不用较早数据替代最终结果。

## 完整结果与回归验证

- 616 个测试、3,988 个子测试通过；src 格式、ruff、两段式 docstring、方法长度及差分空白检查通过。新增基准与专项测试另经 ruff 检查。
- 索引与预算 0 的原遍历差分覆盖两厂商重复接口、别名、源码顺序、前导零 unit、活动状态、增删改名、整列表替换、重排、嵌套独立回滚、根替换、深复制及预算逐出。
- 验证文档和解析器可以在任务存活时被回收，任务结束不留旧节点，超预算和禁用缓存不改变查询结果。
- 语义结果与未过滤的旧匹配器比较完整决策及错误文本，覆盖实际规则样例、随机路径、通配回溯、捕获开头、空语句、引号、节点类型、歧义及非法路径约束。验证跨规则包隔离、18,000 条不整体清空、逐出、任务隔离和输入释放。
- 8 组完整仓库样例同时运行第三轮前版本、新版预算 0、新版默认预算，各自预热后运行三次。配置文本、接口映射、报告内容及拓扑单元格值一致，包括预期失败的样例。

完整样例比较配置文本、映射、`report.json` 和拓扑单元格值；不对性能文件、xlsx ZIP 元数据及其他辅助文件作字节比较。报告顶层 events、errors、warnings、group_conflicts 列表按内容排序，以消除已有的不稳定报告排列。因此它验证报告内容和数量，不声称报告列表字节顺序一致。节点和重复接口的源码顺序由专门测试验证。

小规模完整样例为毫秒级，启用缓存时有快有慢，不能据此认定真实转换端到端必然加速。完整样例主要用于行为差分，热点实验用于定位和验证重复工作减少。

首批完整对照中 `iosxr_bundle` 为 51.90 ms → 95.21 ms；追加七次复测为 41.71 ms → 41.18 ms，该差异未稳定复现。七次复测的 NNI 阶段中位数为 1.83 ms → 1.49 ms。两批数据均保留，追加批次包含每次总耗时、分阶段中位数及缓存计数，避免只保留较快的一次测量。
